**Requerimiento 32.1: Estados de pago**

### Resumen del Requerimiento

El objetivo central de este requerimiento es formalizar la máquina de estados y parametrización de vías de cobro para los pagos de clientes dentro del módulo administrativo/contable. Se incorporan las tablas maestras para tipificar los estados del ciclo de vida del pago ("Borrador", "Pendiente de acreditación", "Aceptado" y "Rechazado") y clasificar los medios de pago según admitan o no acreditación diferida (ej. cheques). A nivel de backend, el sistema debe exponer los catálogos correspondientes y aplicar validaciones automáticas de asignación de estado según la naturaleza del medio de pago, mientras que el frontend debe consumir estos datos dinámicamente y brindar retroalimentación visual mediante badges identificatorios y selectores controlados.

### Backend (Capa de Datos, Servicio y Exposición)

* **Model (`Payment.js`):** Gestionan el acceso y persistencia sobre las tablas maestras `EstadoPago` y `MedioPago`. Deben proporcionar métodos de lectura para consultar colecciones completas (`findAll`) y búsqueda por identificador (`findById`) utilizando sentencias SQL estructuradas sobre MySQL.


* **Service (`payment.service.js`):** Orquesta la recuperación de catálogos y aplica las reglas de correspondencia entre el medio de cobro y el estado inicial del pago. Evalúa si el medio seleccionado es diferido (`es_diferido = true`) para forzar o sugerir transiciones hacia "Pendiente de acreditación", manteniendo "Borrador" como estado preliminar de edición.


* **Controller (`payment.controller.js`):** Expone los endpoints de consulta de catálogos `GET /api/payment-methods` y `GET /api/payment-statuses` mediante Express.js. Valida la correcta respuesta de la capa de servicio y despacha códigos HTTP semánticos (`200 OK`, `500 Internal Server Error`) en formato JSON uniforme.



### Frontend (Capa de Integración y Presentación)

* **Integración API (`payment.service.js`):** Implementa las funciones asíncronas cliente `getPaymentMethods()` y `getPaymentStates()` utilizando la API nativa `fetch` para consumir los endpoints expuestos.


* **UI (`PaymentStatusBadge.jsx` y formularios asociados):** Provee un componente modular de badge visual que mapea el estado del pago a un esquema de estilos con TailwindCSS (ej. neutro para Borrador, ámbar para Pendiente de acreditación, esmeralda para Aceptado y carmesí para Rechazado). Asimismo, puebla dinámicamente los selectores (`<select>`) en los formularios de registro y edición de cobros.



### Reglas de Negocio Clave

* **Parametrización de Cobros Diferidos:** La asignación de estados debe respetar la naturaleza del medio de pago: si se utiliza un instrumento diferido (ej. cheque con `es_diferido = true`), el pago no puede registrarse directamente como "Aceptado" sin antes atravesar el estado "Pendiente de acreditación" o nacer en "Borrador".


* **Consistencia de Estados del Autómata:** Solo son válidos los estados predefinidos en la tabla maestra: "Borrador", "Pendiente de acreditación", "Aceptado" y "Rechazado". Se rechaza cualquier valor fuera de catálogo.


* **Identificación Visual Inequívoca:** La interfaz de usuario debe distinguir visualmente cada estado operativo para evitar que el personal administrativo confunda pagos firmes de aquellos pendientes o rebotados.

##### ⚠️ Gestión de Riesgos y Advertencias de Arquitectura



1. **Acoplamiento por Identificadores Fijos (Hardcoding):** Evitar quemar IDs numéricos de estado en el código JavaScript. Es recomendable definir un diccionario o enumerador centralizado de constantes referenciando los nombres o claves semánticas de los estados para prevenir discrepancias si los índices primarios difieren entre entornos de desarrollo y producción.


2. **Impacto en Saldos de Medios Diferidos:** Un medio diferido con cheque emitido no constituye fondos acreditados. La arquitectura contable debe garantizar que el estado "Pendiente de acreditación" no sea interceptado erróneamente por las consultas de agregación de balances contables hasta tanto se ejecute su acreditación efectiva.
